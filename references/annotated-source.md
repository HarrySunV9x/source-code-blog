# 源码与中文注释规范

展示能支撑当前推理的真实代码，并解释代码如何改变状态。源码保真与讲解完整分别检查，不能用完整函数数量代替解释深度。

## 定位与来源

每个片段前说明它解决的当前问题，以及未缩写的仓库相对路径和原始起止行号，例如：

```text
源码：src/main/java/example/TaskService.java:42-68
所处步骤：提交前检查；决定任务是否进入执行队列。
```

可点击文件链接使用运行环境支持的绝对路径。行号始终指向原文件，不包含后加的教学注释。拆分片段各自标明实际范围；多个不连续片段不能冒充一段连续原文。

## 代码保真与注释语言

- 保持所展示的可执行语句、标识符、常量及其顺序和缩进，不重写、修复或增加执行逻辑后冒充源码。
- 新增教学注释使用中文和源语言的合法注释语法，每条以 `【讲解】` 标识。用户明确要求其他语言时遵从用户。
- 原有自然语言注释需要展示时，中文注释可原样保留；外文注释用忠实中文译文并标为 `【原注释译文】`。说明片段是带译注的源码展示，而非逐字符转录。原文可通过源码定位查阅，不默认把长篇外文再复制一遍。
- 区分原作者说明和自己的解释。译文不加入自己的推断；教学注释中的设计动机若无证据，标明是推断。
- 许可证声明、必须保留的归属信息保持原样。编译指令、构建标记、工具指令等具有机器语义的注释不翻译、不删改，在旁边用中文解释。
- 与当前问题无关的纯说明性原注释可在明确标注“省略非执行说明”的展示版中省略。不能通过删注释隐藏适用条件、前置约束或实现限制。
- 伪代码、概念示意、假设日志放在单独代码块并明确标注，不能混进真实源码片段。

如果自动核验源码，应比较保留的可执行内容与原始范围，并识别明确的注释变换。不要用粗暴的正则删除注释后声称保真：字符串可能包含注释分隔符，部分注释还有机器语义。无可靠解析工具时手工核对关键片段，并如实说明验证范围。

## 按语义展示，不按方法长度决定深度

优先展示支撑当前因果的语义单元。短方法或必须依赖整体理解的方法可以完整展示；长方法按决策、状态更新、交接、错误处理等步骤拆分，在片段间解释上下文和变化。

拆分和省略必须满足：
- 说明进入片段前已成立的条件、尚持有的锁或资源，以及片段之后的去向。
- 保留影响当前结论的校验、分支、状态写入、异常处理、回滚、回调和同步操作。不能把它们隐藏在 `...` 后面。
- 对省略的范围说明位置、作用，以及为何不影响当前结论。不在源码块中放置貌似可执行的省略占位语句。
- 被拆开的控制结构不冒充可独立编译的方法；需要完整上下文时提供定位，而不是复制一份巨大附录补偿。
- 是否省略取决于分析问题。研究统计时，计数和汇总代码是核心证据；不能笼统把监控、统计或格式化列为可省略代码。

研究范围可以大于展示范围。没有全文展示不等于可以不检查关键分支。若当前问题是算法如何工作，片段与正文应覆盖实际选择或转换规则及状态变化，不能只展示分派入口、包装调用或附带计数。关键帮助函数未展示时，其规则仍须在相邻正文或已链接的解释章节中讲清；单独的源码定位不能代替讲解。

## 教学注释写什么

把说明放在最相关的操作前，解释：值来自哪个真实事件、当前条件允许或阻止什么、状态如何变化、下一位使用者是谁、失败后保留或释放什么、同步保证是什么。

不要只把 `if (task == null)` 翻译成“判断任务是否为空”。应根据实际调用方和分支说明空值代表的情形，以及返回后哪些操作不会发生。不能凭空添加“任务可能已被删除”等源码未证明的业务原因。

注释中的字段引用不能成为新的追踪终点。例如“读取 total 字段”不解释 total 的含义；应在相关源码注释或机制说明中追到其实际生产者与更新条件。

## 代码块周围的解释

块前说明读者当前要解决的问题和进入条件。局部代码说明必须在块内紧贴相应语句：参数语义、分支依据、状态变化、返回值与资源处理不能移到块外逐条讲解。块后仅连接跨函数因果、场景推演或机制比较，不用“【讲解】＋编号列表”补偿无注释源码。不要三次重复同一句解释，也不要逐行复述语法。

首次起草参考 [完整注释示例](annotated-example.md)。每章交付前按 [章节验收](chapter-workflow.md#章节验收) 检查真实产物，不以“已经读过规范”视为符合规范。

严格 JSON 等无注释格式保持合法原文，中文说明放在块外。代码片段很长而解释很少时，重新判断是否把“展示源码”误当成了“解释实现”。
