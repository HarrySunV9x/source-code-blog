# 教学验收与独立试作

## 分开检验教学与源码

源码审查按 analysis-and-evidence.md 与 chapter-workflow.md 核对事实和范围。先拿原始问题与源码调查记录对照正文：主要来源、分支、绕行分别在哪里解释？哪些只有名称？再从实现中复查一条没有被主示例覆盖的、会改变结论的路径；若不存在这类路径，说明实现依据，不凑数量。不能只检查成稿已经引用的代码。

教学审查仅凭成稿检验其是否教出了必要认识；结论正确但前提没写出来，也应返修。只读成稿的审查不能证明源码覆盖完整。分别记录“范围与事实核验”和“概念与过程教学”的结果，有任一必讲路径未完成，不能宣布整体通过。格式验证只能证明格式。

主文初稿先做教学自查，防止方向错误扩散。完整大主题交付前使用未参与写作的独立上下文做读者审查（工具与授权允许时）。审查者不会成为真正的初学者，因此必须约束其证据来源，不准用领域知识替作者补步骤。

## 中文注释校验（硬性门槛）

示例代码必须有详尽的就近中文注释，这是独立于“范围覆盖”和“教学可读性”的通过门槛；三者任一项不达标，都不能宣布整体完成。

### 校验步骤

1. 抽取成稿中全部源码展示块（`text` / `c` 等围栏；按 skill 约定，`源码：… 所处步骤：…` 的 `text` 片段头标记块不计入）。
2. 对每个块检查：块内是否至少有一条 `【讲解】` 注释；关键语句——参数/入参约束、分支判定依据、锁与资源的持有或释放、状态写入、返回值含义、错误与回滚路径、交接给下一位使用者的数据——是否都有就近注释；是否存在“块内无注释、靠块后逐条文字顶替”的块。
3. 统计注释密度：按章运行 [校验脚本](scripts/check_annotations.py)（`python3 scripts/check_annotations.py <章节文件>`），确认注释分布覆盖多数展示块，而非只在少数块点缀。脚本会区分“块内注释 / 仅块后相邻注释 / 完全缺注释”三类，其中“完全缺注释”即判不通过。
4. 抽查块外解释：是否与块内重复或冒充代码讲解；块外只应承担概念、跨函数因果与场景推演。

### 不通过判据（满足任一即返修）

- 存在源码展示块完全没有任何 `【讲解】` 注释；
- 关键分支、状态写入或回滚路径只有块外文字讲解，块内无就近注释；
- 注释为“翻译体”（逐行复述语法而未解释真实因果）；
- 注释把源码未证明的业务原因当作事实写入。

返修后必须重新跑本校验并复核受影响章节，不得以“已读过规范”或“其它章有注释”视为通过。机械计数只能报告注释是否存在与分布，不能替代对“注释是否解释真实因果”的语义判断。

## 给读者审查者的任务

输入仅包括本轮成稿路径、目标读者背景和本协议；不提供作者总纲、源码、预期结论、旧稿或纠偏历史。审查者只读成稿，输出 `.work/reader-review.md`：

1. 用自己的话复述文章主题、基本模型和主要推理过程，为每一步指出正文依据。不能只复述标题。
2. 逐个说明主文主要部分新增了什么认识，以及它依赖前文哪项认识。标出缺失前提、跳步、换题或无教学作用的重复，引用具体段落。
3. 从正文选择一个有明确条件的例子，改变一个影响分支或执行结果的条件，仅凭文中规则推导结果。检查正文提出的其他主要来源能否同样解释，不能只选最详细的示例就判整篇通过。正文不足时指出缺什么，不自行补充答案。
4. 检查主文能否独立理解、深读是否兑现解释、基本原理是否被例外打断，以及路线与章节链接是否一致。选取深读中最依赖前提的一段说明判断依据。
5. 列出阻塞教学的具体问题与可选润色，明确通过或需返修。没有证据的“连贯、全面、不错”不算审查。

把外部领域知识才能补出的步骤记录为缺口。不了解某个超出目标读者前提的术语不是读者的过错；但已在正文教会的概念不要求每节重教。不要为了表面线性强迫独立参考章节建立虚假依赖。

## 返修与完成条件

编排者在 `.work/revision-log.md` 记录阻塞问题、修订位置和复核结果；不能只改变标题、加衔接句或添加案例代号。根据断点补概念、重排推导或重新调查。涉及事实的争议交源码审查，不把读者猜测当作事实修正。

复核受影响的主文、深读和链接，并回到原始问题检查其他路径是否有同类遗漏；用户举例不自动缩小任务范围。没有实质新问题时不要无休止润色。主题不明、核心机制只列名字、主要结论缺前提、原理与源码矛盾等未解决问题阻止完成声明。不存在固定字数、代码数量或机械打分的通过门槛。

## 验证 skill 本身

修改教学流程后，在独立上下文给一个真实且有边界的请求，仅提供 skill 路径、原始源码、输出目录、读者需求。不提供已有教程、预期目录、纠偏历史或主文答案；输出到隔离试作目录，不能覆盖正式教程。执行者可以按 skill 自行调查和返修。

随后由另一独立上下文按本协议审查产物，编排者核对关键源码与注释。保留实际结果、发现和修复记录，不把口头承诺当作行为验证。可选择一个与当前主题不同的小模块检验泛化；小模块试作不能证明大主题分章和全文整合稳定，完整主题验证未做时必须明说。

行为验证不要求复制某一份成稿的措辞或目录；验证的是主题清楚、原理完整、细节有据、注释就近，以及无需用户提示便能返修。只做单机制试作不足以证明跨章叙事能力。
