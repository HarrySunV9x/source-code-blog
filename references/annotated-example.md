# 带注释展示的完成样例

下面是虚构的 C 教学示意，不是某个仓库的真实源码；用于说明排版与解释颗粒度。真实文章必须从当前仓库读取实现并给出准确位置。

本段回答：消费者取任务时，如何区分“暂时无任务”与“队列已结束”？进入前不持有队列锁；`closed` 表示生产者不再提交任务，已有任务仍要处理。

```c
int take(struct queue *q, struct item **out)
{
    /* 【讲解】队列长度和关闭标记必须在同一临界区读取。
     * 否则检查完“有任务”后，另一消费者可能先取走最后一项。 */
    mutex_lock(&q->lock);

    if (q->count == 0) {
        /* 【讲解】只有“队列空且已关闭”才表示消费结束。
         * 空但未关闭时，生产者仍可能提交，调用方可以稍后重试。 */
        int result = q->closed ? END : RETRY;
        mutex_unlock(&q->lock);
        return result;
    }

    /* 【讲解】即使 closed 为真，只要仍有任务就继续出队。
     * pop_locked 在持锁时移除队头并减少 count；成功后调用者持有任务。 */
    *out = pop_locked(q);
    mutex_unlock(&q->lock);
    return OK;
}
```

示意推演：初始 `count=1, closed=true`，第一次调用取走最后一项并返回 `OK`；下一次才返回 `END`。若把初始状态改为 `count=0, closed=false`，结果是 `RETRY`。因此“关闭”等于停止新增，不等于立刻停止消费。

本示例只依赖已给出的 `pop_locked` 契约；若文章主题是队列自身的出队算法，则必须继续展示这个帮助函数的实现，不能用此契约作为终点。

注意：块内解释局部代码与条件，块外推演整个行为。不要把条件缩写成“closed 就结束”，也不要将上面的注释重新写成块外编号列表。
